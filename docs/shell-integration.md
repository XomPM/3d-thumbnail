# 탐색기 연동 구조

Explorer가 요청한 크기에 맞추어 작은 COM 연결 DLL이 썸네일 작업자를 실행하고 PNG를 32비트 비트맵으로 돌려줍니다. 파서와 렌더러는 Explorer DLL에 링크하지 않습니다.

## 초기화와 자원 제한

STL, OBJ, 3MF, STEP/STP, PLY, GLB, IGES/IGS, FBX는 `IInitializeWithStream`을 사용합니다. 읽기 전용 스트림을 현재 사용자와 SYSTEM만 접근하는 LocalLow 임시 디렉터리에 복사합니다. 디렉터리와 파일 핸들을 유지해 교체·쓰기 충돌을 줄이고, 원본 스트림 위치를 복구합니다. 완료 후 자신이 만든 임시 파일만 지웁니다.

외부 버퍼가 필요한 `.gltf`는 `IInitializeWithFile`로 원본 폴더를 파악합니다. JSON에 선언된 버퍼만 읽고 상대 경로와 실제 파일 핸들 경로가 모델 디렉터리 아래인지 확인합니다. 상위 경로, URL, ADS, 잘못된 URI, 누락·과대 버퍼를 거부합니다. 디코딩된 버퍼 합계와 JSON+외부 파일 합계를 제한합니다. 외부 텍스처는 읽지 않습니다.

작업자는 최대 15초, 커밋 메모리 1 GiB, Job 안의 프로세스 1개로 제한합니다. 입력 64 MiB와 삼각형 250,000개 제한도 검사합니다. 이 제한은 권한 격리를 제공하는 보안 샌드박스가 아닙니다.

## COM 등록

`shell-formats.json`에 9개 CLSID와 11개 확장자를 정의합니다. `HKCU\Software\Classes`의 클래스·확장자·SystemFileAssociations 및 필요한 현재 ProgID의 썸네일 처리기를 등록합니다. 기본 파일 열기 앱과 UserChoice는 변경하지 않습니다.

개발 환경에서 기본 격리 활성화가 실패하여 현재 배포는 자체 CLSID에 `DisableProcessIsolation=1`을 설정합니다. 연결 DLL은 Explorer 프로세스 안에서 동작하고, 형식 파싱과 렌더링은 별도 작업자에 남습니다. 다른 PC의 격리 활성화 문제를 해결했다고 주장하지 않습니다.

등록 전에 값의 존재 여부, 자료형, 데이터 및 새로 생성할 키를 JSON에 기록합니다. 제거할 때는 현재 값이 우리 설치 값과 일치할 때만 원래 값을 복원하고, 다른 프로그램의 변경은 보존합니다. 비어 있는 생성 키만 제거합니다.

업데이트는 최초 원본 백업을 보존하면서 DLL 경로만 교체합니다. 전환 전에 이전 값과 새 값을 기록하여 중단된 업데이트에서도 혼재된 등록을 제거할 수 있습니다. 다른 프로그램이 이미 변경한 등록이 있으면 업데이트를 거부합니다. 새 버전은 별도 폴더에 두어 Explorer가 로드한 이전 DLL을 덮어쓰지 않습니다.

## 색상과 캐시

작업자는 매 실행 시 `HKCU\Software\3DThumbnail\Settings`의 `AppearanceV1`을 읽습니다. 버전 1바이트 + 배경 RGB 3바이트 + 모델 RGB 3바이트를 하나의 REG_BINARY 값으로 저장합니다. 누락·오류·알 수 없는 버전은 기본 회색으로 복원합니다. 렌더링 API는 명시적인 색상 인자를 받으며 테스트에서 실제 사용자 설정을 바꾸지 않습니다.

설정 창은 파싱이 필요 없는 자체 형상으로 미리보기를 만듭니다. 선택 파일/폴더 갱신은 백그라운드 스레드에서 `IThumbnailCache::GetThumbnail(WTS_FORCEEXTRACTION)`으로 96/256/512/1024 크기를 재생성하고 `SHChangeNotify`로 알립니다. 전역 캐시 삭제나 원본 파일의 내용·수정 시각 변경은 하지 않습니다. 같은 색상을 저장하는 것만으로 기존 캐시가 모두 갱신되지는 않습니다.

## 검증 도구

- `build.ps1`: CTest의 색상·형식·렌더링·프로세스·COM 검사.
- `tests/registration_tests.ps1`: 고유 GUID 테스트 키에서 등록, 자료형 보존, 외부 변경, 중단 복구, 업데이트 검증.
- `scripts/validate-shell.ps1`: 원본 샘플의 별도 복사본으로 실제 Windows 추출, 캐시 반복, 형상 변경, 손상 및 복구 검사. 설치된 처리기가 필요합니다.
- `shell-probe --direct|--shell`: 직접 COM 호출과 Windows Shell 추출을 구분합니다.

이미지 생성 성공만으로 탐색기 화면 표시나 다른 PC 설치 성공을 대신하지 않습니다. 별도의 설치 왕복, 탐색기 화면 확인, 원본 SHA-256 보존 검증이 필요합니다.
